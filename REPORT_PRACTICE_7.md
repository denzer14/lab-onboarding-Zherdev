# Отчет по практическому занятию №7. Анализ потоков данных, дизассемблирование и линтинг.

## 1. Анализ потоков данных (DFA)

### 1.1. Таблица Def-Use цепочек

| Переменная | Def | Use |
|---|---|---|
| `log_entry` | строка 10 исходного примера: финальное присваивание | строка 12: передача в `write` |
| `status` | строка 5 исходного примера; начальное `pending` в исправленном коде | строки 10 и 14 |
| `balance` | строка 6: вызов `get_balance` | строка 7: вычисление `new_balance` |
| `new_balance` | строка 7: вычитание суммы | строка 8: передача в `update_balance` |
| `file` | строка 11: открытие файла | строка 12: вызов `write` |

### 1.2. Выявленные дефекты
- Дефект 1 (Неинициализированная переменная): при `amount <= 0` исходный `status` не инициализирован.
- Дефект 2 (Мертвое присваивание): начальное значение `log_entry` не используется.
- Дефект 3 (Утечка ресурса): исходный файл не закрывается явным образом.

## 2. Дизассемблирование

### 2.1. Восстановленный код

```python
total = 0
i = 1
while i <= 10:
    total += i
    i += 1
```

Результат: `55`.

### 2.2. Пояснение логики

Ячейки `-4(%rbp)` и `-8(%rbp)` соответствуют сумме и счетчику. Счетчик меняется от 1 до 10 включительно.

## 3. Деобфускация

### 3.1. Расшифрованная строка

### 3.2. Анализ угрозы

Команда рекурсивно принудительно удаляет корневую файловую систему и может уничтожить данные и вывести систему из строя.

Запретить `exec`, валидировать данные, применять статический анализ и запускать код в изолированной среде с минимальными привилегиями.
